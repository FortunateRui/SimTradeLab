# TD 9-13 Sequential 信号策略 · 使用说明

> 仅识别 Setup / Countdown 信号，不下单交易。运行环境为 PTrade 回测/交易引擎。
> 所有可调参数集中在同目录 `config.json`，本文档解释每一项的语义、默认值与取值约束。

## 一、文件与目录结构

```
strategies/my_strategy/
├── backtest.py        # 单文件策略实现（数据/信号/策略钩子均在此）
├── config.json        # 策略配置参数
├── 说明.md            # 本文档
├── README.md          # TD 9-13 规则与算法定义
└── doc/               # 设计文档与原始论述
```

策略运行期间会在 PTrade **研究目录** 下自动创建 `TDSignal/` 子目录，并产出：

| 路径 | 说明 |
| ---- | ---- |
| `<research>/TDSignal/config.json` | **必须** 上传到此路径；策略首先尝试从此处读取配置，失败则使用内置默认配置（会打 WARNING 日志）。 |
| `<research>/TDSignal/signals.csv` | 当 `log.csv_output=true` 时，每日新产生的信号事件按行追加。 |

## 二、模块架构

| 层 | 关键类/函数 | 职责 |
| --- | --- | --- |
| 配置层 | `load_config` / `_deep_merge` | 读取 `config.json` 并与默认配置深度合并 |
| 日志层 | `StrategyLogger` | 统一日志前缀 `[TD][sec=...][freq=...][dt=...]`；按级别与开关筛选 |
| 数据层 | `Bar` / `MarketDataFetcher` | 调用 `get_history` 拉取行情，过滤 `volume<=0` 的停牌 K 线；不感知任何信号语义 |
| 信号层 | `SetupMachine` / `CountdownMachine` / `TDSignalProcessor` | 纯计算，输入是 `Bar` 序列，输出是事件列表；不感知任何 IO |
| 输出层 | `SignalRecorder` | 仅做 CSV 持久化；不感知任何信号语义 |
| 策略钩子 | `initialize` / `before_trading_start` / `handle_data` / `after_trading_end` | 在 PTrade 允许的接口范围内组装上述模块 |

> **数据-信号解耦**：信号层完全不知道数据来自 `get_history` 还是磁盘缓存；数据层完全不知道信号是 TD 还是别的。
>
> **无缓存全量重算**：按 README 推荐策略，每次 `handle_data` 都新建 `TDSignalProcessor`，从最近 `lookback_count` 根有效 K 线全量跑一遍状态机，仅取最后一根（=今日）的事件作为当日信号。这与"前复权全量更新"语义一致。

## 三、配置参数详解

`config.json` 按层级组织。所有以 `_` 开头的键视为注释/预留说明，加载时忽略。

### 3.1 `universe`

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `securities` | `list[str]` | `["600519.SS"]` | 待跟踪标的列表，PTrade 标准代码格式 |
| `benchmark` | `str` | `"000300.SS"` | 设置策略基准（仅用于 PTrade 评价指标） |

### 3.2 `data`

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `frequency` | `str` | `"1d"` | 数据周期；本策略**不支持混合频率**，需与 PTrade 软件中策略周期保持一致 |
| `fq` | `str` | `"pre"` | 复权方式：`pre`-前复权（推荐）/`post`-后复权/`dypre`-动态前复权/`None`-不复权 |
| `lookback_count` | `int` | `300` | 每次 `handle_data` 拉取的 K 线条数（含当前周期）。需 ≥ 30 才能覆盖典型 setup+countdown 区段 |
| `min_required_bars` | `int` | `20` | 当有效 K 线（剔除停牌后）数量小于此值时，本周期跳过该标的 |

### 3.3 `backtest`

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `slippage` | `float` | `0.001` | 比例滑点，传入 `set_slippage` |
| `limit_mode` | `str` | `"UNLIMITED"` | `LIMIT` 或 `UNLIMITED`，传入 `set_limit_mode` |

### 3.4 `setup`

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | `bool` | `true` | 是否启用 Setup 信号识别（关闭则不会输出任何 setup 信号，也不会启动 countdown） |
| `require_perfect_for_signal` | `bool` | `false` | 仅在"完美 Setup"成立时才输出 setup 信号并启动后续 countdown |
| `extend_record_max` | `int` | `18` | **预留**。当前实现 setup 第 9 根触发即冻结 setup_bars；该参数预留给后续 Recycle / setup 延伸日志功能 |

### 3.5 `intersection`（**预留**，待后续更新）

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | `bool` | `false` | 是否启用 TD 交叉过滤；当前未实现 |

### 3.6 `countdown`

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `enabled` | `bool` | `true` | 是否启用 Countdown 识别 |
| `type` | `str` | `"sequence"` | `sequence`-序列计数（已实现）；`combo`-组合计数（**预留**） |
| `require_perfect` | `bool` | `false` | 启用完美 Countdown：count==12 后只有同时满足一般条件且满足完美条件的 K 线才进位为 13；否则仅输出 `PLUS_TENTATIVE` 信号 |
| `tdst_cancel_rule` | `int` | `4` | TDST 突破取消规则，5 选 1：<br>1. 最高价 > Setup 中最高的收盘价<br>2. 最高价 > Setup 中最高的最高价<br>3. 收盘价 > Setup 中最高的收盘价<br>4. **收盘价 > Setup 中最高的最高价（默认）**<br>5. 收盘价 > Setup 中最高的真实最高价（max(high, prev_close)）<br>对 Sell Countdown 取反方向 |
| `cancel_on_opposite_setup` | `bool` | `true` | 计数过程中出现反向 Setup 完成 → 取消并启动反向 countdown |
| `cancel_on_same_setup` | `bool` | `true` | 计数过程中出现同向新 Setup 完成 → 取消并以新 setup 启动新 countdown |

预留字段（仅作占位说明，加载时忽略）：

* `_reserved_combo`：组合型 Countdown
* `_reserved_recycle`：Recycle 循环计数（同向 setup 延伸到 18 根触发）
* `_reserved_termination`：TD Termination Count

### 3.7 `log`

| 字段 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `level` | `str` | `"INFO"` | 日志最低级别：`DEBUG` / `INFO` / `WARNING` / `ERROR` / `CRITICAL` |
| `verbose_state_transition` | `bool` | `false` | 是否在 DEBUG 级别详细打印 Setup 状态机的每一次状态转移（数据量较大，建议调试时开） |
| `verbose_countdown_step` | `bool` | `true` | 是否在 DEBUG 级别详细打印 Countdown 每次进位事件 |
| `csv_output` | `bool` | `true` | 是否将每日新产生的信号事件追加写入 `signals.csv` |
| `output_dir` | `str` | `"TDSignal"` | CSV 输出子目录（相对 PTrade 研究根目录） |

## 四、信号事件类型说明

CSV 列：`datetime, security, frequency, category, type, direction, count, extra`

| `category` | `type` | 含义 |
| --- | --- | --- |
| `SETUP` | `BUY_SETUP` / `BUY_SETUP_PERFECT` | 买入结构第 9 根完成（带 `_PERFECT` 表示同时满足完美 Setup 条件） |
| `SETUP` | `SELL_SETUP` / `SELL_SETUP_PERFECT` | 卖出结构第 9 根完成 |
| `COUNTDOWN` | `BUY_COUNTDOWN_PROGRESS` | 买入计数 +1（`count` 字段记录当前计数值，1~12） |
| `COUNTDOWN` | `BUY_COUNTDOWN_PLUS_TENTATIVE` | `require_perfect=true` 且 count==12 时，本根满足一般条件但不满足完美条件，记 `+`，count 不进位 |
| `COUNTDOWN` | `BUY_COUNTDOWN_COMPLETE` / `BUY_COUNTDOWN_COMPLETE_PERFECT` | 买入计数完成（13） |
| `COUNTDOWN` | `BUY_COUNTDOWN_CANCEL` | 买入计数被取消，`extra` 字段携带 `reason=...`：<br>`opposite_setup`-出现反向 Setup<br>`same_setup`-出现同向新 Setup<br>`tdst_break_rule_X`-TDST 突破（X 为规则编号） |
| `COUNTDOWN` | `SELL_*` | 同上，方向相反 |

`direction` 字段：`1` 表示买方向，`-1` 表示卖方向。

## 五、运行流程概要

1. **`initialize`**：加载 `config.json` → 构造 `StrategyLogger`、`MarketDataFetcher`、`SignalRecorder` → 调用 `set_universe / set_benchmark / set_slippage / set_limit_mode`。**不获取任何行情**（PTrade 限制）。
2. **`before_trading_start`**：调用 `filter_stock_by_status(["HALT","DELISTING"])` 刷新 `g.active_securities_today`，剔除当日停牌/退市标的。
3. **`handle_data`**（每周期一次）：
   1. 对每个当日有效标的，二次调用 `get_stock_status('HALT')` 进行保守确认；
   2. 通过数据层拉取最近 `lookback_count` 根 K 线（已剔除 `volume<=0` 的停牌日）；
   3. 新建 `TDSignalProcessor`，全量喂入历史 K 线运行状态机；
   4. 仅取出"最后一根 K 线（=今日）"产生的事件作为当日信号；
   5. 按事件级别打印日志，并写入 `signals.csv`。
4. **`after_trading_end`**：当前仅打印一条 DEBUG 日志，预留扩展位。

## 六、停牌日处理策略

策略采用三层防护，确保停牌日不参与信号计算：

1. **盘前过滤**：`filter_stock_by_status` 剔除当日停牌标的，今日完全不处理；
2. **盘中复核**：`handle_data` 内通过 `get_stock_status('HALT', today)` 再次确认；
3. **历史清洗**：数据层在构造 `Bar` 列表时直接丢弃 `volume<=0` 的 K 线，`SetupMachine` / `CountdownMachine` 收到的永远是有效成交日序列，停牌历史日完全等价于"不存在"，与 README "如果出现中断，就必须重新开始构建"的语义一致——但若关心严格"自然日连续中断"，应将多日停牌视为序列中断，可在后续版本通过新增配置项扩展。当前默认按"有效交易日"序列连续推进。
